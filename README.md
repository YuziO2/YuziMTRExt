# yuzi 的 MTR 扩展

给 **[Minecraft Transit Railway](https://www.minecraftransitrailway.com/) 4.0.5 / MC 1.20.1 / Fabric**
打补丁的私人 mod。三件事：修上游的 bug、把 MTR3 里好用而 4 里没有的行为搬回来、加几样自己要用的东西。

装上 jar 就行，不需要改 MTR 自己的配置。服务端和客户端都装（有些功能只在其中一边生效，下面会标）。

许可证 **AGPL-3.0** —— 绳索屏蔽门的模型资源派生自同样 AGPL 的
[RailwayAesthetics-Future](https://github.com/Jomeyer/RailwayAesthetics-Future)。

---

## 它能干什么

### 让 MTR3 的自定义车在 MTR4 里正常跑

MTR4 会自动转换 MTR3 格式的资源包，但转换路径上有一串坑。装上之后下面这些症状都不再出现：

| 症状 | |
|---|---|
| 整车不渲染，只剩几个零碎部件 | 为 NTE 写的包用了 `<文件名>.obj/<部件名>` 这种部件名，MTR4 不认 |
| 离开一辆车 60 秒再回来，猛卡一阵，然后**那辆车的门永久打不开** | 模型缓存被回收后门映射不会重建 |
| 开门时该开的一侧不开、对侧开，关门就恢复 | OBJ 门部件被翻转了两次 |
| 每个车厢进视野都要重新卡一次 | 缓存分桶错配，预热白做 |
| 贯通道尺寸和车不匹配 | 上游把尺寸写死了，不看车宽 |
| 一个方向两边门全开、反方向两边全不开 | 镜像部件的判定盒跑到了对侧 |
| 门状态指示灯常亮，开灯关灯同时亮 | MTR3 的分侧门条件字符串在 MTR4 里全部匹配不上 |

需要按车配置的只有两项：`consistSizes`（编组长度，用于预热）和 `gangwayOverrides`（贯通道尺寸）。
不配也能用，只是每个车厢第一次进视野会卡一下 —— 因为模型现在常驻内存，**只卡这一次**。

> ⚠️ 模型常驻内存的代价：**换资源包请重启客户端**，不要在游戏内重载 —— 观察到过整套资源包被清空、
> `options.txt` 里的 `resourcePacks` 被清成 `[]`。

### 找回 MTR3 的手感

- **能走到窗边** · `widenFloorsToInterior` —— MTR 其实没有座位碰撞箱，是过道地板的宽度把你夹住了。
  现在地板自动撑到车厢内壁，自适应车宽，不用逐车配数字。
- **shift 短按坐下 / 起立** · `shiftToCrouch` —— 长按仍然是下车，两者不打架。

### 排图与运营 · 仅服务端

- **分交路停站时长** · `perRouteDwellTime` —— 同一个站台，不同交路停不同时长，编排缓急接续的前提。
  在站台仪表板的「途径本站台之路线」列表里逐条填秒数，留空 = 跟随站台总时长（灰字实时显示继承来的值）。
  存在 MTR 自己的存档里，没装这个 mod 也能读那份存档。
  **改完要重新生成一次该车厂的路径才生效。**
- **刷新路径不再清空在跑的车** · `minimalPathRefresh` —— MTR4 只要刷新就把全线的车删掉重等，排图没法做。
  现在只在「距离映射真的变了」时才清：改停站时间、改速度等级、改信号量都保车，改轨道几何才清。
- **改停站时间不用刷新路径** · `applyDwellTimeWithoutRefresh` —— 仪表板一保存，在跑的车立刻按新时长停。
  （屏显和时刻表的到发推算要等下一次刷新路径才跟上。）
- **时钟跳变不再吞班次** · `stabiliseScheduleAnchor` —— `/time set`、睡觉跳夜、重启补时会让按游戏时间
  发车的线路凭空出现一个几个班距宽的空洞，绕环线转、不自愈。现在跳变会被识别并拒绝跟随。
- **侧线车辆最高速** · `vehicleMaxSpeed` —— 车厂侧线面板「车辆减速度」下面多了一行，填 km/h，
  0 = 不限。设了之后列车按 **min(线路限速, 车辆最高速)** 跑，PIDS 上的到发时刻也按这个速度推算。**两端都要装**
  （面板那一行在客户端，限速在服务端）。
  - 是**硬上限**：晚点时「延迟时加速」也不会让车超过它。
  - **只管自动运行**，手动驾驶照旧只受「最高手动速度」约束。
  - **改完不用手动刷新**：保存时发现最高速变了，会自动替你「刷新路线」一次，效果和手动点那个按钮完全一样。
    在跑的车保存那一刻就按新速度跑。刚改完的那一趟可能被判早点一次，被「提前到达站台时等候」吃掉后自动归位。
  - 配合上面的「刷新不清车」，**无限重复的车厂**不会清车。**非无限重复的车厂**：上限调低、单程变长后，
    每条侧线能接的班次可能变少，班次号超出范围的在途车会在下一刻消失 —— 这是刷新本身的行为，改加速度也一样。
  - 既然会自动刷新，就和手动刷新一样：**线路正在施工、路不通的时候别改**，寻路失败会把车厂路径清空。
  - 最低 10 km/h（填 1～9 按 10 算）：时刻表推算是按毫秒逐步模拟的，速度越低越费时，全在模拟线程上跑。
  - 寻路**不考虑**这个上限（同车厂的侧线共用一份路径），不会因为车跑不快而改走更短的路。

> ⚠️ 因为刷新不再清车，MTR 那个「给已经有车的轨道加信号闭塞会互锁」的上游 bug 没法再靠刷新路径绕过。
> 在已通车的线路上加信号闭塞前，先把那段的车清掉。

### 升降式绳索屏蔽门

同一个站台停不同门距的车时，固定门位的屏蔽门没法用。这是现实里的解法：整排绳网一起升降，不区分门位。

三个方块，在创造模式的「铁路设施」页里：

| 方块 | |
|---|---|
| **绳索** `rope_barrier` | 绳网本体，5 根绳按门开度升降 |
| **立柱（带屏显）** `rope_barrier_post` | 正面是一块点阵 PIDS：线路名 + 右对齐到达时间 / 开往终点站 / 前方依次到站 |
| **立柱（纯白）** `rope_barrier_post_blank` | 不要屏幕的场景 |

摆法是 `立柱-绳-绳-绳-立柱-绳-绳-立柱`，**整排会一起动** —— 立柱能把开度导通过去，所以中间隔多少根都行。
方块是双高的，放下时占两格。

时序可调：绳网升起速度是车门的 `ropeBarrierSpeedMultiplier` 倍（默认 2 倍）；关门前
`ropeBarrierCloseLeadMillis`（默认 1.5 秒）绳网就已经完全落下；落下前 `ropeBarrierWarningLeadMillis`
（默认 3 秒）开始响 `ropeBarrierWarningCount`（默认 3）声提示音。

### 只能从车门上下车 · `boardOnlyThroughDoors`

MTR4 做了「只能从车门下车」，但没做「只能从车门上车」—— 没对准车门往前走会直接穿过车体掉进轨道，
配上绳网屏蔽门尤其明显。现在车厢侧面有一堵隐形墙：撞上去过不去，但**可以贴着车身滑到门口**，
到了门口直接上车。

`boardingWallExtraWidth`（默认 0.5）控制墙面比车厢宽出多少。**如果贴着墙时视角穿进车皮、或者还会
掉进缝里，就把它调大** —— 车辆配置里声明的宽度常常比模型实际车宽窄。

车厢连接处一并挡住；车头车尾没做。运行中的列车默认不拦（`boardingWallWhenMoving`）。**纯客户端。**

### 报站与广播器

- **交路的「关掉下一站播报」只关语音** · `routeFlagMutesNarratorOnly` —— 上游那个开关会把
  聊天栏的下一站文字和讲述人语音一起关掉。改成只关语音，文字照常显示。
  配合自制 TTS 时要的就是这个：语音自己来，文字留着。**纯客户端。**
- **广播器可以选择全部交路** · `announcerAllRoutes` —— 上游只让你选**附近的**交路，
  而且**选不到隐藏交路**。现在全都能选。
  只作用于广播器；基础列车感应器和列车时刻表感应器保持原样。**两端都要装。**

  > 隐藏交路只在广播器的选择器里出现，**不会**跑到站台线路图、PIDS 或铁路标志上 ——
  > 这条数据是单独取的，没有动 MTR 的共享数据。
  >
  > 刚打开广播器的头一两帧、以及服务端没装本 mod 时，选择器会退回上游那份「附近的」列表。
  > 这种时候已经选中的远处/隐藏交路在主界面上会显示成**空行**（选中状态并没有丢，
  > 只是那份列表里查不到名字）。等一下再打开选择器就正常了。

- **站台广播器**（新方块） —— 摆在站台上，按到站/发车时刻**向四周放**资源包里的音频。
  和 MTR 自带的「广播器」不是一回事：那个只有**车上的乘客**听得到、而且是贴耳播放、
  没有提前量；这个是站台广播，服务端统一触发，周围所有人同时听到同一声。**两端都要装。**

  一块方块里可以放任意多条规则，每条规则是「哪个站台 + 哪条交路 + 哪段音频 + 什么时候放」：

  | | |
  |---|---|
  | 站台 | 自动列出本方块所在**车站的全部站台** |
  | 交路 | 列出该站台停靠的交路，**含隐藏交路**；也可以选「全部交路」 |
  | 音频 | 从资源包里挑，带试听 |
  | 时机 | 以**到站**或**发车**为基准，前/后 X 秒，**开始播**或**播完** |

  「到站」和 PID 上那个「X 分/X 秒」同一个口径，「发车」和 JCM 的发车倒数器同一个口径。
  偏移秒数填负数就是基准**之后**。选「播完」时起点会自动往前推一个音频时长 ——
  时长在选音频时自动量出来（读 ogg，不解码），界面上也能手改。

  **规则可以复制粘贴**：悬停在规则上点铅笔左边的复制按钮，到任意一块站台广播器（包括别的车站）
  点「粘贴规则」。音频和时机原样照搬，站台和交路按本站重新对：

  - 指定了交路的规则 → 找本站这条交路停靠的站台；**本站没有这条交路**就把交路置为「未选择交路」，
    站台也清掉，规则标成「（未生效）」等你补。
  - 「全部交路」的规则 → 找本站和原站台**停靠交路重合最多**的那个站台（同一条线同一方向）；
    一条都不重合就清掉站台。
  - 同一个车站里粘贴 → 原样复制。

  > 喇叭属性是整块共享的：音量（半径 = 16 × 音量）、是否只认实时班次、
  > 以及可选的长方体范围（框内贴耳播放、框外完全听不到，照抄 JCM 的声音循环器）。
  >
  > 三语报站动辄十几秒，「发车前 3 秒播完」的 17 秒音频起点会落在车刚进站甚至没进站的时候。
  > 规则界面底部那行「实际起点」就是给这个用的，配的时候看一眼。
  >
  > **「仅实时班次」怎么选**：不勾时，还没出库的车按计划时刻也会触发 —— 提前量大的规则
  > （比如「到站前 8 分钟」）要靠这个才响得起来；代价是这趟车如果晚出库超过 20 秒，会**再播一次**。
  > 勾上就不会重播，但车出库之前的时刻一律不触发。提前量只有几秒到一两分钟的规则，勾上更稳。

### 渲染与音效修复

- **开光影后 MTR 的屏蔽门、PIDS 文字整个消失** · `fixShadowPassEatingRenderQueue` —— 阴影 pass 把
  渲染队列吃掉了，主画面拿到的是空的。
  修好之后可以关掉 MTR 自己的「开启光影时不显示阴影」，OBJ 模型的影子都正常。
- **重连后走行音消失，玩一会又自己回来** · `fixLegacySoundThrottle` —— 上游的限流时间戳在重连时没跟着
  归零，静音时长等于上一段连接的时长。只影响非 BVE 音效的车，门音一直是好的。
- **走行音响度巨大、音质破** · `fixScheduledSoundDuplication` —— 上游把每个音效播了 N 遍并相干叠加，
  幅度直接翻 N 倍削波。**修好之后走行音会明显变小**，那才是正常响度。

### 新增内容

- **180–500 km/h 的高速轨道** —— 补上 180 / 250 / 280 / 350 / 380 / 400 / 450 / 500 八档，
  每档普通 + 单向共 16 个物品，在 MTR 自己的「核心」创造页里。颜色和 MTR 现有十档的色系拉开了。
- **网页地图的头像地址可配置** · `playerAvatarUrl` —— MTR 把 `mc-heads.net` 写死在前端里，
  自定义登录（LittleSkin 之类）的 UUID 在那边查不到，地图上全是史蒂夫。
  模板支持 `{uuid}` 和 `{name}`，例如 `https://littleskin.cn/avatar/player/{name}`。**改服务端。**

## 配置

`config/yuzimtr.json`，每个功能一个开关，出问题好二分。装了
[「模组菜单」](https://modrinth.com/mod/modmenu) 的话大部分开关有图形界面。

服务端和客户端是**各自独立的两份配置**。排图那几项跑在服务端，在客户端改是没用的
（界面里仍然列着，是为了两边不一致时能一眼看出来）。

`consistSizes` / `gangwayOverrides` / `defaultConsistSizes` 是「正则 → 结构」的映射，只在 json 里改。

MTR 自己的 `config/mtr.json` 里那个 `preloadResourcePattern` **可以留空** —— 配了 `consistSizes`
的车会自动进入预加载。留空反而更快，因为 `consistSizes` 只列存档里真正在用的车。

**改完配置要重启** —— 缓存寿命是在对象构造时烤进去的。

## 排错

出问题先把对应的开关关掉，确认是不是这个 mod 引起的。几个调试开关会往日志里打详细信息：
`debugCacheLogging`（模型重建）、`debugDoorMapping`（门左右侧映射）、`debugDwellTime`、
`debugPathRefresh`、`debugRopeBarrier`、`debugBoardingWall`。

实现细节、上游 bug 的成因、注入点的选择理由，都在 [AGENTS.md](AGENTS.md)。
